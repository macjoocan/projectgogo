# AES 작업 히스토리 — Heroll 메타데이터 복원

정리일: 2026-11-20 · 실제 작업 완료일: 2026-09-22

**Heroll 2.0.3에서 AES-256-CBC 복호화와 zlib 압축 해제를 거쳐 메타데이터를 복원했다.** 복원 후 전체 필드 토큰과 테이블 이름·타입을 대조했다. 이 문서는 기존 로컬 기록을 정리한 것으로, 복호화를 새로 실행한 결과가 아니다.

| AES 적용 대상 | 별도 파일에 들어 있던 메타데이터 복원 경로 |

게임 실행과 게임 서버·CDN 요청은 하지 않았다는 기록이 남아 있다. 네이티브 코드 복원, AES 메타데이터 복원, 타입 구조 해석은 연결된 작업이지만 서로 다른 단계다. 모든 보호 처리가 AES였다는 뜻은 아니다.

## 작업 순서

중간 단계별 시각은 기록에 없어 임의로 붙이지 않았다. 아래는 2026-09-22 기록 안에서 확인되는 진행 순서다.

### 1. 코드 복원과 메타데이터 이상 확인

로더의 복사·변환 경로를 따라 분석용 코드 사본을 복원했다. 압축 스트림의 정상 종료, 남은 입력 바이트와 복원 길이를 검사했다.

당시 메타데이터에는 필드 레코드 122,712개가 있었다. 이 중 30,678개의 토큰이 구조 검사에 실패했고 92,034개는 기대한 태그를 가졌다. 일정한 위치에서 실패한다는 이유만으로 값을 추측해 고치지 않았다. 초기 기록의 “메타데이터 미복원”은 이 단계의 상태다.

### 2. 실제 메타데이터 로딩 경로 확인

일반 파일 매핑 경로만으로 Unity 메타데이터 복원을 설명할 수 없었다. 로더 문자열과 메타데이터 매핑 경로를 추가로 조사했다. 그 결과 실제로 사용하는 별도 파일을 확인하고, 파일 이름과 기준 에셋의 해시 관계를 대조했다.

### 3. AES-256-CBC와 zlib 처리 확인

관찰한 디코더가 별도 파일에 **AES-256-CBC**를 적용하고, 이어서 **zlib** 압축을 해제하는 것을 확인했다. 패딩과 압축 종료도 함께 검사했다.

복원한 메타데이터 크기는 **28,140,936바이트**다. 복원 후 필드 토큰 **122,712개 전부**가 기대한 `0x04` 태그를 가졌다. 단순히 파일이 생성됐다는 사실만으로 성공 처리하지 않았다.

### 4. 선언과 테이블 대조

원본 사본의 복원 대상 코드 구간을 교체해 분석용 ELF를 준비했다. `Il2CppDumper`는 덤프 오류 없이 끝났다. 보호 관련 경고는 남았지만, 후속 선언·타입 구조 판독과 테이블 대조가 통과했다.

테이블 **164개, 14,593행**의 멤버 이름·타입을 확인했다. CSV에서 관찰한 enum **59종**도 네이티브 선언과 일치했다. 상점 `ShopProductList`의 추가 멤버는 계산 속성 `ProductType`으로 확인했다. 실제 직렬화 순서를 대조했고 420행 모두 `Consumable=0`이었다.

### 5. 계층 복원과 최종 검증

타입 구조를 읽는 백엔드 3종은 각각 별도 프로세스로 실행해 결과를 캐시했다. 이를 이용해 씬·프리팹 계층의 필드를 다시 읽었다. 최종 계층 처리 기록은 약 **174초, 피크 1.59GiB**다.

| 검증 대상 | 최종 기록 |
|---|---:|
| 필드 토큰 | 122,712개 모두 통과 |
| 테이블 | 164개, 14,593행 이름·타입 확인 |
| 관찰된 enum | 59종 대조 통과 |
| 날짜·빈 배열 | 날짜 1,216개, 빈 배열 261개 대조 통과 |
| 계층 | 씬 9개, 프리팹 468개, 노드 74,540개 |
| MonoBehaviour 필드 복원 | 77,275개 중 77,261개, 99.9819% |

계층의 필드 복원율은 전체 복원 작업의 결과다. AES만 적용하면 모든 필드를 바로 읽을 수 있었다는 뜻은 아니다. 외부 참조·정렬·배열 표현과 사용자 정의 Dictionary 해석도 수정했다.

## 남은 한계

14개 객체의 필드는 끝까지 복원하지 못했다. 13개는 원본의 스크립트 포인터가 0이고, 1개는 패키지의 전체 타입 정의에서 해당 클래스 선언을 찾지 못했다. 이름을 추측하지 않고 `fields:null`로 남겼다.

검증 대상은 패키지의 저장 데이터와 구조다. 현재 서버 설정, 게임 실행 중 실제 동작이나 시간대 변환을 검증한 것은 아니다. 완료된 복호화를 다시 수행하거나 초기 실패 보고서로 최종 결과를 덮어쓰지 않는다.

## 다른 복호화 작업과 구분

**Clash of Critters의 패키지 복호화는 Blowfish와 LZ4를 사용한 별도 사례다.** Heroll의 AES 작업과 혼동하지 않는다. 이 문서는 확인한 Heroll 사례를 정리하며, 전체 작업 공간의 모든 AES 사용처를 전수 조사한 목록은 아니다.
