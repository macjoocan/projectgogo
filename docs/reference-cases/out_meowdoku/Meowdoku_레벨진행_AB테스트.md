# Meowdoku 1.20.0 — 레벨 진행 구조와 A/B 테스트

출처: APK 디컴파일 소스(`scripts_src/`, Godot 4.6.1 GDScript 917개). 코드 위치는 `scripts/module/...` 기준 상대 경로.
분석일 2026-10-16. 서버에서 내려오는 실험 배정 비율·실험 종료 여부는 APK 에 없어서 알 수 없다.

## 1. 요약

- 일반 레벨은 **고정된 레벨 목록이 아니다.** 레벨 번호마다 판 크기·난이도 등급을 계산하고, 레벨 뱅크(47,687개)에서 조건에 맞는 퍼즐을 골라 낸다.
- 난이도는 **플레이어 실력에 따라 오르내린다**(DDA). 연속 클린 승리 시 상승, 연속 실패·재도전·부활 시 하락한다.
- 선택 규칙 전체가 A/B 테스트 `normal_level` 값에 묶여 있다. 실험 값 108개, 전용 선택 전략 클래스 87개.
- 실험에 배정되지 않은 사용자는 대조군 전략 `NLControlStrategy`를 쓴다. 이 문서의 2~4절은 대조군 기준이다.
- 일부 실험군은 21레벨부터 **서버 추천 퍼즐**을 받아 쓴다. 해당 사용자의 레벨 구성은 APK 만으로는 재현할 수 없다.
- A/B 설정은 모두 160개. 110개는 게임 코드에서 직접 참조되고, 50개는 직접 참조가 없다(종료됐거나 다른 경로로 쓰이는 실험).

## 2. 레벨 선택 흐름

`gameplay/selector/level_selector.gd` → `LevelSelector.select(level_num)`

1. `ABTestManager.normal_level` 값으로 선택 전략을 고른다(`strategy/level_selection_strategy_resolver.gd`). 등록되지 않은 값은 대조군으로 넘어간다.
2. 전략이 컨텍스트를 만든다: 판 크기 → 하드 레벨 판정 → 난이도 등급 → 하루 첫 판 완화 → 티어 보정.
3. 특수 레벨이면 지정 퍼즐을 낸다.
4. 아니면 뱅크 후보군을 만들고(`LevelData.build_pools`) 커서 순서대로 꺼낸다.
5. 후보 검사: 최종 검증(`FinalLevelValidator`) → 단일 칸 영역 수 제한 → 중복 검사(`PuzzleDeduplicator`, 회전·반전 동형 포함).
6. 통과한 퍼즐을 전달하고, 재도전용 데이터·프리필 위치·기법별 단계 수를 붙여 저장한다.

## 3. 대조군 규칙

레벨별 값은 `Meowdoku_levels_summary.xlsx` 의 `진행규칙(대조군 1-300)` 시트에 있다.

### 3.1 판 크기 (`selector/context/size_modifier.gd`)
| 구간 | 크기 |
|---|---|
| 1~10레벨 | 4, 5, 6, 6, 8, 6, 7, 8, 9, 7 |
| 11레벨~ (10판 주기) | 8, 10, 10, 9, 10, 10, 9, 10, 10, 10 |

`size_cycle` A/B 설정(기본 `CYCLE_V3_D`)은 등록돼 있지만 선택 코드에서 참조하지 않는다. 판 크기는 위 표로 고정이다.

### 3.2 하드 레벨
- 21레벨 이상이면서 10의 배수인 레벨. 등급 r5, 티어 N 으로 고정한다.
- 하드 레벨에서는 등급 계산과 하루 첫 판 완화를 건너뛴다.

### 3.3 특수 레벨 (`selector/provider/special_provider.gd`)
| 뱅크 | 레벨 |
|---|---|
| SP(특수 패턴) | 10, 20, 30, 40, 50, 55, 60, 62, 70, 75, 80, 90, 100, 123, 456 |
| LK(LinkedIn 일일 퍼즐) | 200, 250, 314 |

### 3.4 난이도 등급
등급(rank)은 풀이에 필요한 최고 기법 단계(1~5)다. 내부 값 "전략(strategy)"이 등급과 티어를 정한다. 전략 1~4는 같은 번호의 등급(티어 N), 5는 r4 티어 H, 6은 r5 티어 N, 7은 r5 티어 H.

| 구간 | 전략 범위 | 비고 |
|---|---|---|
| 1~5레벨 | 1 고정 | |
| 6~20레벨 | ≤2 | |
| 21~50레벨 | ≤3 | 3이면 2~3 중 균등 무작위 |
| 51레벨~ | 2~4 | 3 이상이면 2~상한 중 균등 무작위 |

"상한"은 아래 DDA 가 정한 현재 전략이다.

### 3.5 동적 난이도 DDA (`game_state/game_state.gd` 승리 처리부)
6레벨부터 적용한다. 하드·특수 레벨 등 일부는 제외한다.

| 항목 | 규칙 |
|---|---|
| 승급 | 연속 클린 승리 2판(51레벨~ 1판)마다 +1 |
| 강등 | 연속 실패 2판(20레벨 이하 1판)이면 −1 |
| 재도전 강등 | 21레벨~, 같은 전략에서 재도전한 레벨이 2판 연속이면 −1 |
| 재도전·부활 승리 | 이긴 판이라도 재도전 또는 부활을 썼으면 −1. 다음 레벨이 하드·특수면 그다음으로 미룬다 |
| 하한 | 1 (101레벨~ 2) |
| 상한 | 20레벨까지 2, 50까지 3, 100까지 4, 200까지 5, 이후 6 |

- "클린" 이 깨지는 행동: 힌트, 위치 찾기, 메모(draft), 마우스 도구, 설정(기어) 버튼.
- DDA 상한은 5·6 까지 오르지만 대조군 일반 판 선택기는 51레벨부터 4로 자른다. 대조군 일반 판의 최고 등급은 r4 다.

### 3.6 하루 첫 판 완화 (`DailyFirstEasyModifier`)
- 하루 한 번, 그날 첫 일반 판의 전략을 1 낮춘다(전략 2 이상일 때).
- 전날 이어 하던 판에 고양이·표시·오답이 남아 있으면 그날 기회는 없어진다.

### 3.7 뱅크 혼합 (`gameplay/model/level_data.gd`)
- 50레벨까지: 일반 → LKStyle → GC 뱅크를 이어 붙인 목록을 순환한다.
- 51레벨부터(메인 경로):
  - 마지막 LK 계열 퍼즐 이후 4판이 지나면 LinkedIn 변형 퍼즐(lk_mod) 1판을 끼운다. 예약된 lk_mod 번호(20, 30, 53, 71, 72, 75, 114, 141, 164)는 제외한다.
  - 10×10 r3·r4 는 일반 뱅크를 빼고 LKStyle·GC 만 쓴다.
  - GC 뱅크는 10×10 r1 과 11×11 에서만 쓴다.
  - 판을 회전·반전한 8가지 변환으로 같은 퍼즐을 다시 쓴다(lk_mod 제외).
- 진행 위치는 판 크기·등급·티어별로 따로 저장한다.

### 3.8 후보 검사와 완화
- 단일 칸 영역 수 제한: 1차 스캔은 2개 이하, 최종 검사는 1개 이하(`single_region_num` 기본값, `single_limit_at` = 1). SP·LK·lk_mod 는 예외.
- 같은 퍼즐(동형 포함)은 최근 기록과 비교해 다시 고른다.
- 후보가 없으면 7단계로 완화한다: 분산도 필터 해제 → 단일 칸 1차 제한 해제 → A/B 단일 칸 제한 해제 → 티어 해제 → 낮은 등급 → 높은 등급.

### 3.9 프리필
1~10레벨은 정답 1칸을 미리 채운다. 6레벨까지는 2칸 이상 영역의 칸, 7레벨부터는 1칸짜리 영역을 우선한다.

## 4. 서버 추천 레벨 (`level_rec/level_rec_manager.gd`)
- 실험군 `SERVER_REC_V2`(11515), `SERVER_REC_ACTIVE/STANDBY`(11710/11711), `SERVER_REC_V3_*`(11923~11925)이 대상.
- 플레이 기록(진행 상태·결과·레벨)을 서버로 보내고, 추천 퍼즐을 큐로 받는다. 남은 큐가 8개(v2 이상 10개) 이하가 되면 미리 받는다.
- v2 이상은 20레벨 전에는 요청하지 않는다. v3 는 21레벨부터 서버 큐를 쓴다.
- v3 하드 판정: 서버 퍼즐 등급이 4 이상이면 하드. 하드끼리 최소 6레벨 간격을 둔다.
- 큐가 비거나 검증에 실패하면 로컬 규칙(NL11900)으로 대체한다.

## 5. A/B 테스트 구조

### 5.1 동작 방식 (`abtest/abtest_manager.gd`, `abtest/config/ab_config_base.gd`)
- 실험 하나당 설정 클래스 하나. `key`(서버 키)와 `default_value`를 가진다.
- 값은 서버 원격 설정에서 받아 정수 또는 문자열로 읽는다. 받기 전에는 기본값을 쓴다.
- `normal_level` 등 일부 키는 그룹 전환 이력을 따로 저장한다(`_SWITCH_STORE_INCLUDE`).
- 전체 목록: `ab_configs.csv` (키, 기본값, 실험 값 상수, 코드 참조 파일).

### 5.2 normal_level 실험 계보
전략 클래스는 `selector/strategy/nl_<값>_strategy.gd`. 전체 대응표: `normal_level_groups.csv`, 대조군 대비 차이: `normal_level_strategies.csv`.

| 기준선 | 특징 | 이 기준선을 쓰는 실험 |
|---|---|---|
| NLControl (0) | 3절의 규칙 | 미배정, GF_* 4개(11505~11508) |
| NL11502 | 등급 3 이상을 가중치로 뽑는다: 상한 3 → r2 30%·r3 70%, 상한 4 → r2 20%·r3 30%·r4 50% | 115xx~118xx 다수, iOS 119xx(11951~11972) |
| NL11709 (v1.13 롤백) | 11502 가중치 + 진행 속도 커서 | Android 119xx(11901~11922), 12007~12009 |

여기서 "진행 속도 커서"(`DeliveryPacedCursor`)는 크기·등급별 진행 위치와 lk_mod 삽입 간격을 전달 기준으로 센다.

### 5.4 그 밖의 A/B 설정
