## [기준 / 확인한 불일치]

원본 프리팹을 APK에서 다시 읽었다:

- BouncerCylinder_4: `assets/bin/Data/66d1282fdecb34353a5a74a9806fd2c0`. 루트 회전identity, Renderer 위치0, **자식 Mesh.localPosition.y=-2**. 정상 콜라이더 중심y0, 높이약3.99.
- BouncerCylinder_3: `assets/bin/Data/a57d09df9d25b462a9c148b0008524e0`. 루트 회전identity, **자식 Mesh.localPosition.y=-1.5**. 정상 콜라이더도 루트 중심 배치.

즉 raw 메시의 minY0만 보고 **프리팹 루트도 바닥 피벗**이라고 해석하면 안 된다. 원본은 Mesh 자식을 반 높이만큼 내려 루트 중심에 맞춘다.

현재 프로토 `data/entity-catalog.json`은 두 종류에 minY0, h3/4를 기록한다. `web/main.js:447`은 다음 식으로 rigidbody와 중심 정규화 메시를 배치한다:

`py = e.p[1] + entry.minY + h/2 + spawnY`

따라서 공통 spawnY를 제외하고 **원본보다3형은1.5, 4형은2 높게 시작**한다. `web/meshes.js`는 raw 메시를 중심 기준 ±h/2로 정규화하므로 원본 자식의 -h/2와 같은 보정 의미가 이미 그 정규화에 들어간다. 그 위에 중심 자체를 다시+h/2 올리는 현재 경로는 원본 프리팹 루트 배치와 다르다.

또 `B.spawnSettleSec=0.5`, `freezeUntilTouched=true`; `settleSpawn()`는 첫 화면 전에 dynamic으로 물리를 돌리고 다시 Fixed로 만든다. **발사0인 이미지도 원본 저술 직후 자세가 아니라 프로토의 0.5초 정착 이후일 수 있다.** 잘못 띄워진 기둥의 낙하/접촉이 기울어진 상태로 고정되는 유력 경로다. 이 인과 전체를 이번에 시뮬 A/B로 실측하지는 않았다.

프로토 randomYaw는 Y축만 회전한다(`yawFor`/YAW_Q). 그 코드 자체가 이 원통을 옆으로 눕히는 회전은 아니다. 원작의 randomYaw 런타임 구현 범위는 이번에 추가 추적하지 않았다.
