# 인게임 아이템 + 서버 없는 교체용 이벤트 구현 인계

2026-09-29. 사용자가 **정식 서버 데이터 없이 교체용 규칙으로 구현**하도록 요청했다. 원본을 전부 판독할 때까지 기다릴 필요가 없다. 이 문서의 이벤트 일정·수치·보상·실패 정책은 모두 **[자체/교체용 v1]**이다. 원본 클래스/필드와 RVA는 참고 근거이며, 이벤트 계산식까지 원작 동일하다는 주장이 아니다.

Claude 구현 담당: 기존 `Assets/_RS/Runtime/Meta`에 결합하되 실제 파일 구성은 현재 프로젝트에 맞춘다. Codex는 D: 자료만 작성했으며 Unity 코드 변경/실행을 수행하지 않았다. 이전 `systems_audit_20260929/README.md` 기본 사이클·연승 정정은 계속 유효하다.

## 전달 파일

- `ITEMS.md`: 3종 사용/취소/소모/효과/복구와 원본 수치.
- `EVENTS.md`: 이벤트 6종의 구체적인 오프라인 규칙, 상태/보상/화면/실패 처리.
- `offline_catalog.json`: 로컬 교체용 수치·보상 표. **이벤트 부분은 전부 자체값.**
- `source_declarations.json`: 원본 아이템/이벤트 클래스 선언. **필드/메서드 존재 근거**, 함수 본문이 아니다.
- `INTEGRATION.md`: 공용 API·원자 저장·중복 방지·UI 큐·구현 단계·QA.

원본 아이템 저장값 전체는 `../systems_audit_20260929/system_values.json`, 네이티브 근거는 같은 폴더의 `disassembly`와 `method_index.json`을 재사용한다. 리소스와 해금 UI는 기존 Claude 추출본을 결합한다.

## 바로 결정된 방향

1. HTTP/CDN/로그인/광고 SDK/실제 결제/실시간 매칭 **없이** 로컬 JSON과 저장 파일로 실행한다. 요청한 구현 범위 자체가 오프라인이다.
2. 매칭형 이벤트는 로컬 모의 상대다. 상대 점수는 저장한 seed와 경과 시간으로 재현한다. 실제 유저/실시간 경쟁으로 표시하지 않는다.
3. 원작 SO 수치는 아이템 효과의 기준으로 사용하되, 불명확한 소모·취소 정책은 문서의 자체 정책으로 통일한다.
4. 교체용 이벤트는 기기별 단독 저장. 진행 중 정의를 바꾸지 않도록 configVersion/설정 스냅샷을 이벤트 인스턴스에 보관한다.
5. 구현 순서: 아이템 완성 → 일일 미션/연승 사다리 → 수집 → 생존 → 단기 레이스/리그. 설정에는 6종을 모두 넣고 로비에서는 핀 3개+이벤트 목록으로 접근한다.

현재 수치는 체험 가능한 출발값이며 경제 밸런스 검증값이 아니다. 수치 교체는 JSON 수정으로 끝나도록 설계한다. 기존 기본 클리어 코인 15/40/50과 이벤트 보상은 별개다.
