# 일회용 실험실 준비 상태

## 최신 v3 결과: 초기 실행 33.6초 관찰 완료, Google Play 확인 오류에서 정지

**결론:** 제어 채널의 반복 검사 및 제한된 초기 실행 관찰은 완료했다. 실제 플레이 또는 게임의 모든 가능한 통신을 검증한 것은 아니다. 현재 오프라인 실험에서는 게임이 Google Play 확인 오류 화면에 머물러 플레이 단계로 넘어가지 못했다. 온라인 접속·로그인·라이선스 우회·탐지 은폐는 수행하지 않았다.

- ADB 기본 사용자 경로 문제를 별도로 재현했고, 전용 사용자 경로를 모든 호출에 통일했다. 또한 설치된 ADB의 `tcp:127.0.0.1:5041` 리슨 옵션 비지원 오류를 기록하고 지원 형식 `tcp:5041`으로 바꾼 뒤 실제 바인딩이 127.0.0.1인 것을 확인했다. 이것들이 이전 모든 오류의 단일 원인임을 입증한 것은 아니다.
- 전용 ADB 서버를 foreground 모드의 독립 프로세스로 실행하고, 클라이언트는 `-H 127.0.0.1 -P 5041`로 고정했다. stdout/stderr/종료 코드를 별도 수집했다. 게임 없는 상태에서 서버 PID와 리스너를 확인하며 80개 명령을 반복했고 전부 성공했다(`adb_stability_v3.json`).
- 새 일회용 환경에 원본 해시가 일치하는 APK 3개를 설치했다. 호스트 44개 규칙 전수 검사와 게스트 IPv4/IPv6 OUTPUT 차단을 통과한 뒤 게임을 실행했다.
- `game_offline_v3.json`의 `Completed=true`, 관찰 시간 33.5819991초, 관찰 샘플 5개. 전용 프로세스군(서명 확인된 OS 콘솔 포함)의 외부 TCP 연결 수는 각 샘플에서 모두 0이었다. 이는 주기적 관찰이며 모든 순간/UDP 송신의 전수 증거는 아니다.
- 게스트 차단 규칙은 검사 때 유지됐고 게임 프로세스도 5개 샘플에서 계속 관찰됐다. 게임 UID의 IPv4/IPv6 DROP 카운터는 0이었다. 경로 단계 차단과 시스템 UID 대행 가능성이 있어 이를 무통신 근거로 해석하지 않는다. 시스템 전체 DROP 카운터와 호스트 UDP 소켓 수는 JSON에 별도로 보존했다.
- 최종 액티비티는 `com.pairip.licensecheck.LicenseActivity`. 스크린샷은 “Something went wrong”, Google Play 활성화/최신 버전 확인을 요구한다. 파일: `D:\99.기타\android-analysis\royalsmash-disposable-20260915\logs\game_offline_v3.png`. 오류 문구만으로 원인을 네트워크/루팅/라이선스 중 하나로 단정하지 않는다.
- 호스트·게스트 UTC 시각은 가까웠지만 PCAP 시간축을 독립 보정하지 못했다(`CaptureClockCalibrated=false`). 캡처 구간 0개 주장을 하지 않는다.
- 게임 강제 중지, 전용 emulator/QEMU/netsimd 종료, 전용 ADB 서버 종료를 수행했다. 폐기 시 실제 경로/링크/리스너/프로세스 부재를 확인하며 `game_v3_20260916_disposal_result.json`을 생성한다. 원본·분석 결과·로그·화면·방화벽 규칙은 유지한다.

**다음 범위:** 온라인 전환 없이 가능한 정적 분석으로 돌아갈 수 있다. 이 초기 실행 관찰을 “게임사가 알 수 없음”이나 “전체 통신 검증 완료”로 표현하지 않는다.

**판정:** 앞선 conhost 오탐은 해결됐으나 게임 통신 전체 검증은 여전히 미완료다. 게임 재실행 전에 게임 없는 환경에서 ADB 제어 채널의 안정성과 오류 보고를 먼저 검증해야 한다. 이번 한 번의 TCP 관찰이나 게임 UID 카운터를 전체 무통신/절대 비탐지 근거로 확대하지 않는다.

## 최종 추가 결과: Windows UDP 실제 차단 확인

게임과 무관한 `UdpFirewallProbe.exe`에 전용 UDP 발신 차단 규칙 `RoyalSmash-UdpProbe-20260916`을 적용하고, 사용자 승인 후 문서용 예약 주소 `192.0.2.1:49263`에 합성 데이터 19바이트 1개(TTL 1)를 송신 시도했다. 게임사 주소나 게임 데이터는 사용하지 않았다.

송신 함수는 성공을 반환했으나, WFP 기록에서 해당 앱·UDP(17)·소스 포트 51753·목적지 포트 49263이 일치하는 발신 `FWPM_NET_EVENT_TYPE_PUBLIC_CLASSIFY_DROP` 이벤트를 확인했다. 차단 필터 ID는 `108479`, 동작은 `FWP_ACTION_BLOCK`, `filterOrigin`은 정확히 전용 시험 규칙이다. 따라서 이 시험 패킷은 Windows 방화벽이 실제 차단했다.

원시 `udp_windows_probe_result.json`의 `Success=false`는 처음 예상한 소켓 오류 10013이 나오지 않았다는 뜻이다. 패킷 차단 실패를 의미하지 않는다. 최종 판정은 상관관계를 대조한 `windows_udp_drop_verified.json`을 기준으로 한다. 원시 결과와 WFP XML은 그대로 보존했다.

**범위:** Windows 전용 시험 프로그램의 UDP 차단 동작 검증 완료. 에뮬레이터/게임 패킷 자체를 실행해 검증한 것은 아니며, 절대적인 비탐지 보장도 아니다. 게임과 에뮬레이터는 실행하지 않았다. 전용 시험 프로그램 차단 규칙은 유지하며 전역 감사/로깅 설정은 변경하지 않았다. 기존 폐기 결과와 원본 분석 파일도 유지했다.
