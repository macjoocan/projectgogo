# 구현 순서와 검증 시나리오

모두 [자체] 이식/QA 제안. 원본 상수와 분기 근거는 README 및 JSON 참조.

1. 상태 모델: Lobby / PrePlay / Playing / Settling / ContinueOffer / Won / Lost / Result. 시도 ID, 완료 레벨 스냅샷, 보상 지급/하트 차감/팝업 종료 플래그를 별개로 관리.
2. 데이터 주입: 초기 저장 변수, LevelRewardConfig, BoosterPurchaseConfig. 기존 저장은 초기값으로 덮지 않음. 레벨 발사 수는 레벨 데이터에서 읽음.
3. 로비/시작/설정/재도전/충전창 배선. 장면 재진입 시 버튼 이벤트 중복 구독 방지.
4. 일반 발사/부스터/장애물 완료 보고와 마지막 발사 안정 대기. 원본 받침 상대 안정 판정은 별도 함수로 유지.
5. 이어하기 가격·발사량 계산, 지불 성공 후 재개, 실패/포기 하트 처리. 광고/IAP는 검증된 성공 콜백만 보상.
6. 성공 보상·레벨 진행을 UI와 분리. 로고/색종이/runId/스킵 → 결과창 → 로비 또는 다음 시작 정책.
7. Tween/커브/RectTransform과 기존 스프라이트/폰트를 결합. [자체] 임시 연출과 원본 저장값을 구분.

| 시험 | 기대 결과 |
|---|---|
| 정상 시작 | 하트 선차감 없음, 레벨 moves 사용 |
| 하트 0 | 시작 UI에서 충전 흐름; unlimited 예외 동기화는 별도 시험 |

| 일반 발사 | 한 발당 1 감소, 종료된 시도 무시 |
| Infinite 활성 후 2초 대기하고 첫 발사 | 첫 발사부터 3초 구간 시작 |

| 움직이는 받침 위 정지 물체 | 월드 속도만 보고 무한히 불안정으로 오판하지 않음 |

| 광고 취소/실패/중복 콜백 | 성공하지 않은 보상 없음; 중복 보상 없음 |
| 저장 후 앱 재시작 | 초기 코인/부스터 재지급 없음; 타이머는 저장 정책 유지 |

이번 전달에서는 위 시나리오를 Unity 실행으로 통과시킨 것이 아니다. `verification.json`은 출처/직렬화 및 순수 가격 계산의 검증 결과다. Claude 측 구현 후 실제 PlayMode 시험 결과를 별도 기록한다.
