# 구매·광고: 배선 준비만

2026-09-29 사용자 지시 반영. 원본 경제 흐름은 README 참고. 이 파일의 인터페이스 설계는 `[자체]`이며 원작 클래스 선언이 아니다.

## 지금 준비할 것

- 아이템 ID, resourceType, 수량1, 가격(700/1500/500), 광고 허용/쿨다운 상태를 데이터로 유지.
- 구매/광고 버튼과 팝업 표시 슬롯을 둔다. provider가 없으면 '연결 준비 중' 상태 또는 비활성 버튼으로 처리한다.
- `RequestPurchase(itemId, requestId)` 및 `RequestRewarded(itemId, requestId)` 호출 지점만 만든다.
- 결과 종류: `Success`, `Cancelled`, `Failed`, `Unavailable`. 미연결 기본 provider는 `Unavailable`을 반환한다.
- 구매/광고 결과를 받는 한 곳에서 UI 갱신과 후속 선택을 처리하도록 구조만 준비한다.
- 잔액 부족→상점 이동은 `RequestOpenShop` 훅만 둔다. 실제 상점 라우터 연결은 보류한다.

## 지금 연결하지 않을 것

- 실제 결제·광고 SDK/네트워크 호출, 광고 성공 자동 처리.
- 버튼 탭만으로 코인 차감, 아이템 지급, Armed 변경.
- 미연결 상태의 가짜 성공 응답. 테스트 성공 주입은 명시적인 개발 전용 기능으로 격리한다.

## 나중에 연결할 때의 계약

1. provider 결과와 지갑 변경 주체를 하나로 정한다. provider가 이미 지급한 결과를 UI에서 다시 지급하지 않는다.
2. requestId로 중복 응답을 걸러낸다. 요청 중 버튼 중복 탭을 잠근다.
3. 취소·실패·미연결이면 지갑·재고·준비 상태를 유지한다.
4. 성공 후 보유량이 팝업을 열 때보다 증가했으면 팝업 종료 뒤 선택을 시도한다. prelevel은 다음 시작 예약, 인게임은 현재 게이트를 검사한다. 자동 발사는 없다.
5. 레벨/세션이 바뀐 뒤 도착한 응답은 현재 대포를 자동 준비시키지 않는다. 지갑 정산과 현재 화면 효과는 분리한다.

## 이번 준비 완료 기준

- provider 미등록 탭 → Unavailable, 코인/재고/Armed 변화0.
- 기존 보유 아이템 사용과 Barrage 예약은 provider 유무와 무관하게 동작.
- offer 데이터와 버튼 상태는 유지되어 후속 배선 시 UI를 다시 만들 필요가 없음.
- 실제 연결·성공 처리 검증은 미완료로 기록.

Unity 프로젝트 구현은 Claude 담당이다. Codex는 이 계약과 원본 근거를 전달하며, 이 문서 작성만으로 C: 구현 완료를 주장하지 않는다.
